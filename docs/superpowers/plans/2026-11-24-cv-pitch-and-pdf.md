# CV Pitch, Personal Projects and PDF Download Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Open the CV with a services-style pitch, add an undated personal projects section, rewrite
every text in a short, confident voice, and offer the CV as a downloadable PDF on /cv.

**Architecture:** Two features, two PRs, in order. `010-cv-pitch` extends the content source
(`resume.json` and its schema) with a pitch field and personal-project marking, and renders both in
the shared `CvDocument` (so /cv, the shell CV app and the terminal all get them). `011-cv-pdf` prints
the built /cv page to `/cv.pdf` with Playwright Chromium during `npm run build`, falling back to a
committed PDF with a staleness check if Vercel's build image can't run Chromium.

**Tech Stack:** TypeScript, React 19 (server-rendered), Node 26, Vitest, Playwright Chromium,
JSON Resume 1.3.1, speckit, Vercel.

**Spec:** `docs/superpowers/specs/2026-11-24-cv-pitch-and-pdf-design.md`

This repo is spec-first (constitution I, II, III, XI). The code-level tasks for each feature are
generated by speckit into `specs/<feature>/tasks.md` and carry the `FR-###` IDs CI traces. This plan
fixes the decisions and the order; the speckit artifacts hold the code steps. Do not write feature
code before the feature's `spec.md` is Approved and its design gate is signed.

## Global Constraints

- Node 26: run `nvm use` before any npm script.
- Never name the pitch's source site, or any personal product (or its repo), anywhere in the repo:
  specs, docs, code, comments, commits, PR text. Enforced by review; grep the diff before each PR.
- No Claude or AI attribution in commits or PRs (CLAUDE.md).
- Voice: short, confident, first person, problem first; no slogans ("I deliver." is out), no filler
  adjectives, no invented metrics.
- Every CV text draft goes through GPTZero, then ZeroGPT, in Chrome; revise flagged lines; the
  owner approves the wording and sees any lines still flagged. Owner approval wins.
- Personal projects: four entries, generic names, no `startDate`/`endDate`, keywords from each
  repo's real stack.
- Skills: Next.js moves from "Also Familiar With" to "Web Frameworks & Libraries"; the rest of that
  group stays.
- PDF: A4, served at `/cv.pdf`, download name `Alex-Profir-CV.pdf`, matches the print view.
- New routes go in `vercel.json` (`/cv.pdf` must not fall through to the 404 rule).
- For text-only changes run `npm run content-check` and affected tests; CI runs the full suite. No
  full `npm test` while another vitest runs on the machine (check `ps`).
- Commit and push each checked change on the feature branch (Conventional Commits). The owner
  merges.

## Review Focus

1. **Pitch missing or empty** in `resume.json`: the section and its heading are left out, as every
   other empty section is (004 FR-004), and section numbers stay continuous. → Task A4 test.
2. **Undated personal project**: renders with no date line, no "Present", no stray separator, in
   /cv, the shell CV app and the terminal's `projects`/`cv` output. → Task A4 test.
3. **Personal and client projects in one `projects[]`**: each appears in exactly one section; the
   terminal's `projects` command shows both groups, labelled. → Task A4 test.
4. **The download link inside the PDF and print**: the link is a site element, hidden in print, so
   the PDF doesn't contain its own download button. → Task B4 test.
5. **Offline and build failure**: offline, the service worker serves `/cv.pdf` from cache or the
   link fails visibly (stated in 011's offline section); a build where Chromium fails exits non-zero
   rather than shipping /cv with a dead link. → Task B3 and B4 tests.
